# Профиль /tech

Прочитай корневой `AGENTS.md`. Вход: технический вопрос, план, фактический стек и ограничения. Текущий агент читает этот профиль, выполняет анализ и возвращается к сохранённому этапу; отдельный консультант не запускается.

Для Android следуй [ANDROID.md](../ANDROID.md). На bootstrap выбери совместимые стабильные JDK/Gradle/AGP/Kotlin/Compose compiler/BOM/KSP, Navigation и SDK, закрепи версии и проверь сборкой. Kotlin-first API и Compose обязательны. Подтверди Gradle tasks, AVD/API/ABI и доступный UI-драйвер. Для boot используй штатный SDK launcher либо подтверждённую возможность текущего инструмента. MCP и конкретный клиент не обязательны.

1. Проверь фактические возможности среды и возможность решения стандартной библиотекой/имеющимися зависимостями.
2. Для новой библиотеки сравни необходимость, совместимость, лицензию, поддержку, безопасность, размер, производительность, транзитивные зависимости, стоимость эксплуатации и удаления. Изменчивые сведения проверяй по официальным источникам.
3. Выбери минимально достаточное решение с аргументами, версией/совместимостью, проверкой и откатом. Если оно выходит за политику, выполни product-consultation с return_phase и выбери допустимую альтернативу либо сохрани BLOCKED. Явные ограничения пользователя и обязательные разрешения среды нельзя отменять решением product; повторную консультацию по уже активному вопросу не запускай.
4. Сохрани решение в материалах задачи и `workflow/decisions.md` по необходимости. Зафиксируй PASS либо конкретный BLOCKED и вернись к планированию/реализации.

Не устанавливай библиотеку только ради оценки. Не расширяй требования. Технический анализ включает архитектуру, данные, сборку и тестовую инфраструктуру.
