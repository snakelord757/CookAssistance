# Профиль /bugfix

Прочитай корневой `AGENTS.md`. Вход: локальная запись бага, воспроизведение, expected/actual и план `/planer`. Профиль выполняет текущий агент последовательно; другие профили подключаются чтением их файлов без создания субагентов.

Для Android соблюдай [ANDROID.md](../ANDROID.md). Воспроизводи UI-баг на указанном AVD/API/окне доступным UI-драйвером, сохраняй evidence/logcat и связь APK/SHA. Используй validation_scope=fix: regression и затронутые соседние сценарии; полная матрица — на milestone по AGENTS.md.

1. Составь план диагностики. Подготовь fix-ветку от согласованной базы в выделенном checkout; worktree необязателен. Соблюдай owned_paths и зависимости. Зафиксируй убедительный baseline FAIL либо используй уже сохранённое точное crash/UI evidence.
2. Исследуй историю и diff, сравни known-good/known-bad; при возможности используй git bisect в изолированном checkout. Укажи culprit SHA и причину либо доказательства неполной истории/изначального дефекта; не выдумывай виновный коммит.
3. Назначь regression-проверку по типу дефекта: содержательный тест для кода либо проверку воспроизведённого противоречия/ссылок для документации. По возможности докажи FAIL до исправления и PASS после. Исправь причину минимальным изменением, сохраняя корректное поведение и публичные контракты.
4. Прочитай `profiles/unit-test.md` и `profiles/smoke_scenario.md`, выполни подготовку тестов и сценариев до финального review. Выполни назначенные проверки и подготовь полный незакоммиченный снимок кандидата по AGENTS.md; commit до security gate запрещён.
5. Прочитай `profiles/review.md` и выполни отдельный проход review. При замечаниях вернись к bugfix, исправь и проверь новый снимок в пределах лимитов. Затем прочитай `profiles/smoke.md` и выполни regression/затронутые UI-сценарии на Android-кандидате. Не повторяй неизменившиеся проверки без причины.
6. Внутри product-loop вернись к этапу SECURITY после PASS проверок по profiles/product.md; при прямом запросе bugfix заверши отчёт в его scope. Сохрани результат: причина, culprit SHA или неопределённость, fix/candidate SHA, APK provenance, отчёты и статус. `PASS` требует review и всех назначенных проверок; недоступная среда — `BLOCKED`.

Если дефект существует только в родительской ветке, зафиксируй проблемный SHA и необходимые импортированные коммиты отдельно от собственных fix-коммитов. Не amend baseline родителя. Переноси исправление обратно без дублирования его реализации; при общей истории предпочитай fast-forward/cherry-pick --ff. После интеграции проверь родительский кандидат; зависимость снимается по проверенной интеграции, а Done — по правилам публикации.

На переходах сохраняй checkpoint, attempts и resume_phase. При resume используй существующую ветку; сначала интегрируй pending patches. Повтор той же сигнатуры обновляет прежний локальный дефект и счётчик; не создавай рекурсивные цепочки и не меняй task ID для обхода лимитов. Выбор следующей задачи выполняй на этапе product.

При прямом запросе профиля security gate также обязателен до commit. Генерация и исправления проходят только через [Gateway](../docs/llm-gateway.md).
