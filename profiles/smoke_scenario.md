# Профиль /smoke_scenario

Прочитай `AGENTS.md` и [ANDROID.md](../ANDROID.md). Вход: фича, план, критерии, applicationId/variant, реестр и матрица. Этот этап выполняет текущий агент, читая профиль без запуска другого исполнителя.

1. Изучи фичу и сценарии, исключи дубликаты. Определи конечный scope по плану: task/fix/milestone.
2. Создай/обнови `tests/smoke/android/<scenario-id>.md`: ID/task/критерии, цель, данные/backend, package/variant/APK provenance, AVD/API/ABI/окна, выбранный UI-драйвер и его возможности, boot/readiness/install/launch, шаги/expected/evidence, таймауты и очистка. Общий lifecycle можно ссылать на smoke.md.
3. Используй наблюдаемые проверки и реальные semantics/resource IDs; selectors не выдумывай. До появления UI запиши требования к наблюдаемости и проверь их перед исполнением. Покрой happy path и затронутые cold start/empty/error/offline/Back/IME/permissions. Адаптивность назначай representative-конфигурациями по AGENTS.md, без полного произведения параметров. Upgrade, чистая установка и process recreation имеют разные предусловия.
4. Обнови `tests/smoke/android/index.md`: обязательность, конфигурации и покрытие критериев. Старый `tests/smoke/index.md` относится к CLI-инструментам. Если драйвер не умеет действие, оцени доступную альтернативу по tech; иначе сохрани BLOCKED. Обязательный сценарий нельзя молча сделать необязательным.
5. Сохрани файлы в кандидате до review, не меняя production-код на этом этапе. Внутри цикла вернись к return_phase; smoke выполняй только при готовом кандидате и назначенном этапе. При прямом запросе подготовки сценариев верни файлы и отчёт без запуска прогона.

Выход этапа: PASS/BLOCKED, список сценариев и соответствие критериям. Подготовка сценариев не доказывает их прохождение.
