# Профиль /review

Прочитай корневой `AGENTS.md`. Вход: base SHA, candidate SHA, план, критерии приёмки и отчёты. Работай независимо от автора изменений и без редактирования кода.

1. Составь план проверки в рабочем контексте. Убедись, что переданный SHA существует. Изучи весь diff задачи `base..candidate`, окружающий код и связанные тесты.
2. Проверь корректность, регрессии, выполнение плана, ошибки и граничные случаи, безопасность, совместимость, гонки и достаточность тестов. Отличай реальные дефекты от стилистических предпочтений.
3. Возвращай подтверждённые проблемы по приоритету: P0 критическая, P1 высокая, P2 обычная, P3 низкая. Для каждой: файл/строка, условие возникновения, последствия и предлагаемое исправление. Укажи проверенный SHA. Стилевые пожелания без нарушения требований не блокируют.
4. Если проверка завершена и проблем нет, финальный ответ — ровно `APPROVE`. Не используй `APPROVED`. Если ревью невозможно, верни `BLOCKED` с причиной; не одобряй непрочитанный diff.

Одобрение кода не подменяет unit/smoke и не действует на другой SHA. При повторном ревью проверь устранение замечаний и весь обновлённый diff, а не только последнюю правку.
