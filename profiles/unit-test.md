# Профиль /unit-test

Прочитай корневой `AGENTS.md`. Вход: задача, критерии, SHA/кандидат, команды и политика покрытия. Текущий агент выполняет этот этап последовательно в ветке задачи без запуска субагентов.

Для Android используй [ANDROID.md](../ANDROID.md): Gradle unit tasks (src/test) для ViewModel/UiState, repositories, преобразований и ошибок; kotlinx-coroutines-test и fakes вместо живой сети. Предусмотренные Compose/Room/Android instrumentation (src/androidTest) запускай отдельно от UI smoke на выделенном эмуляторе. Python suite не является Android unit. Для уточнения module/variant/tasks прочитай `profiles/tech.md` и выполни его инструкции.

1. Изучи изменённое поведение и тесты, сопоставь критерии с рисками. Процент покрытия вспомогателен.
2. Добавь содержательные тесты непокрытых важных ветвей: нормальные случаи, границы, ошибки, регрессии. Не зеркаль реализацию в expected и не ослабляй тест ради PASS. Для небольших правок документации применяй scope AGENTS.md.
3. Меняй только назначенные тесты/фикстуры в текущей task-ветке; worktree необязателен. При дефекте production-кода сохрани локальную находку и перейди через product к dev/bugfix; не исправляй его незаметно в тестовом этапе.
4. Запусти назначенный unit-suite и покрытие, если настроено. Сохрани команду, окружение, SHA плюс незакоммиченные изменения, exit code и отчёт. После включения тестов в кандидат итоговые результаты связывай с его SHA по правилам переноса проверок. Runtime checkpoint/отчёты не требуют коммита; исходники/тесты нельзя скрывать в runtime.
5. При FAIL создай/обнови локальный дефект в `workflow/backlog.json` и состоянии задачи по дедупликации. Различай app/test defect и infrastructure blocker. При отсутствии runner выполни анализ по tech; отсутствие обязательных тестов не является PASS.

Сохрани PASS/FAIL/BLOCKED, карту покрытия, изменения тестов, отчёт и ID дефектов; затем вернись к return_phase внутри цикла; при прямом запросе unit-test заверши отчёт в его scope. Не повторяй неизменившиеся проверки.
