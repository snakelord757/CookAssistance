# Профиль /smoke

Прочитай корневой `AGENTS.md`. Вход: итоговый SHA, все сценарии из реестра, тестовая среда и MCP.

1. Составь план прогона. Проверь соответствие сборки заданному SHA, доступность приложения, MCP и тестовых данных. При несоответствии — `BLOCKED`.
2. Через доступные MCP-инструменты выполни все сценарии реестра, включая существующие. Сохраняй фактические результаты и доказательства шагов: логи, снимки экрана/ответы, время, окружение и SHA. Не заменяй выполнение чтением кода.
3. Для каждого сценария поставь `PASS`, `FAIL` либо `BLOCKED`. Восстанавливай тестовые данные, чтобы сценарии не влияли друг на друга. Повтор временного сбоя ограничен общей политикой и не удаляет сведения о первом падении.
4. При провале составь отчёт, создай/обнови Trello-дефект и приложи отчёт. Для недоступной инфраструктуры создай соответствующий блокер. Используй дедупликацию и pending-операции из `AGENTS.md`.
5. Верни сводку: всего/пройдено/провалено/заблокировано, отчёт, SHA, ID карточек. Успех только если выполнены и прошли все сценарии; пустой реестр при наличии требующей smoke функциональности — блокер.

Не редактируй код и не меняй ожидаемые результаты во время прогона. После исправления требуется новый прогон на новом SHA.
