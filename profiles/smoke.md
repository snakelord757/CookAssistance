# Профиль /smoke

Прочитай `AGENTS.md` и [ANDROID.md](../ANDROID.md). Вход: итоговый SHA, согласованные validation_scope/сценарии/матрица, module/variant/applicationId, APK с build manifest и AVD. Текущий агент выполняет этап последовательно без субагентов. Выбери доступный UI-драйвер по возможностям среды: MCP, Appium, UI Automator либо эквивалент; конкретный харнесс не требуется.

1. Подтверди кандидата и результаты назначенных build/lint/unit/instrumentation. Сохрани команду сборки, variant, applicationId/versionCode, путь APK, SHA-256 и source SHA. При неизвестном происхождении пересобери штатным Gradle task.
2. Получи список AVD штатными средствами SDK, выбери конфигурацию из плана и запусти её, если подходящий выделенный экземпляр ещё не работает. Проверь реальные возможности инструмента boot; при их отсутствии используй SDK emulator launcher. Команды адаптируй к ОС/shell; на Windows фоновый launcher запускай скрыто. Не создавай второй экземпляр занятого AVD и не подменяй его физическим телефоном.
3. Дождись boot с ограниченным таймаутом (по умолчанию 180 секунд): ADB state/sys.boot_completed и доступность UI-дерева/экрана в драйвере. Свяжи serial с AVD/API/ABI. Адресуй этому устройству все действия; instrumentation и сторонние процессы не должны менять его одновременно.
4. Установи и запусти проверенный APK доступными инструментами. ADB допустим для подготовки и управления; smoke требует фактического взаимодействия с Android UI и наблюдения UI-деревьев/снимков с проверкой expected/actual. Одного успешного CLI-вызова или отсутствия crash недостаточно. Имена/аргументы инструментов проверяй по текущей документации.
5. Подготовь данные/backend, permissions, locale, тему, font scale, ориентацию и сеть. Не маскируй миграцию очисткой данных. Сбрасывай только тестовое приложение на выделенном AVD.
6. Выполни назначенные сценарием проверки из реестра. Для task/fix — согласованное подмножество, для milestone — полный утверждённый набор. Используй реальные semantics/resource IDs, UI-дерево и screenshots для визуальных требований. Проверяй expected каждого шага и затронутую адаптивность по плану; матрицу самовольно не расширяй.
7. Сохраняй результаты по мере прогона: PASS/FAIL/BLOCKED/NOT RUN, SHA/APK hash, AVD/serial/API/окно, драйвер/команды/аргументы, actual/expected, время, evidence и logcat при сбое. Создай/обнови локальную запись дефекта по дедупликации. Отсутствие обязательной возможности UI-драйвера или boot — infrastructure BLOCKED. При первом блокирующем FAIL действуй по диагностическому окну AGENTS.md, сохрани NOT RUN для остатка и перейди к исправлению.
8. Восстанови настройки и очисти собственные тестовые данные. Останови только запущенный этим прогоном и больше не нужный AVD. Проверь неизменность кандидата. Сохрани сводку назначенной матрицы и evidence, освободи устройство и вернись к return_phase внутри цикла; при прямом запросе smoke заверши отчёт без запуска новых задач.

Не меняй код/ожидания во время прогона. PASS допускается при покрытии всех обязательных элементов scope выполненными или обоснованно перенесёнными результатами. Отсутствие приложения/реестра/необходимого AVD — blocker. CLI smoke инструментов не засчитывается как Android smoke. После фикса проверь новый SHA/APK по правилам AGENTS.md.
