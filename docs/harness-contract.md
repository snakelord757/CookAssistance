# Контракт подключения харнесса

Рабочий запуск допускается только из [защищённой установки runtime](runtime-integrity.md).
Редактируемая source-копия не является доверенной; прямой CLI-запуск блокируется.


Контракт версии 2 отделяет локальную защиту данных от генерационной модели и
от отдельного security-запроса к той же модели. Наличие AGENTS.md не устанавливает
перехватчик и не считается доказательством подключения.

## Обязательные возможности

До чтения приватных файлов внешним агентом интегратор обеспечивает:

1. Доверенную установленную копию контроллера: Python 3.11+, Git, доступ к audit
   и политике. Копия находится вне checkout, который изменяет генератор.
2. Перехват полного исходящего запроса **до отправки**, включая system/user,
   историю, результаты инструментов, вложения, вспомогательные запросы и retry.
   Для HTTP, WebSocket и SDK нужны реально используемые точки перехвата.
3. Локальную сериализацию в `{stage, system, context}` без потери полей.
   Сетевой адаптер получает только `ContextGate.authorize()` export. Нельзя
   проверять одно представление, а отправлять исходный объект или добавлять к
   нему непроверенный контекст. Неподдерживаемые форматы/бинарные вложения — BLOCK.
4. Политику вне генерируемого checkout, недоступную агенту для записи по ACL;
   оператор явно разрешает точный обезличенный export. Агент не одобряет сам
   реальные новые данные. Синтетические preflight fixtures не дают таких прав.
5. Один stateless backend/model/config для генерации и review. Review — отдельный
   запрос, только security-промпт и разрешённый снимок без истории генерации.
   Credentials не входят в prompt/audit; отдельный DeepSeek не требуется.
6. Установленный commit gate. Обязательные gates нельзя заменять ответом агента
   «проверено». Для защиты от намеренного обхода владельцем машины нужны
   отдельные OS/CI/server-side ограничения.

Отсутствие пунктов 2–4 блокирует приватную работу в данном харнессе, а не только
финальный commit. Если файл уже попал в контекст внешней модели, gateway не
может отменить эту передачу. Первичная настройка выполняется локально на
публичном/синтетическом материале.

## Этапы

Допустимы `planning`, `generation`, `correction`, `review`, `security`,
`summarization`, `title`, `tool_result`, `retry`. Все используют одинаковый
exact-release gate. `tool_result` нужен, когда отправка результата — отдельный
вызов; если он часть запроса generation, проверяется весь этот запрос.
При смене stage/context/system требуется новый допуск. Неизвестный stage — BLOCK.

## Поведенческий preflight

Доверенный коннектор предоставляет команду, запускающую **его обычный путь
отправки** с синтетическими входами и подменённым локальным адресом назначения.
Конфиг вне checkout содержит только `{"command":["absolute-executable", "..."]}`.
Команда получает `--probe <absolute-json-path>`. Файл содержит:

- `request`: полный `{stage, system, context}`;
- `policy`: путь к синтетической release policy;
- `audit`: путь к audit (в негативном сценарии намеренно недоступен);
- `destination`: URL реального временного HTTP-приёмника на 127.0.0.1;
- `token`: синтетический транспортный credential, не ключ модели.

Коннектор должен применить политику/аудит тем же способом, что в обычной работе,
и доставить ровно публичный export как JSON POST на destination. Exit 0 после
успешной передачи; exit 2 при отказе без отправки. Для нативного provider API
коннектор должен использовать свой обычный final-payload перехватчик и тестовый
транспорт. Отдельная имитация фильтра вместо реального пути запрещена.

`harness_preflight.py` запускает 45 проверок: для каждого из 9 этапов точный
обезличенный export достигает приёмника, а отсутствие допуска, изменение
контекста, отзыв допуска и отказ аудита не дают ни одного запроса. Простого
exit 0 или заявления «подключено» недостаточно. Stdout/stderr коннектора не
попадают в логи. Сами probe-файлы содержат только синтетические данные.

```powershell
python scripts/harness_preflight.py --repo D:/isolated/task --connector-config D:/private/security-review/harness.json --audit D:/private/security-review/preflight.jsonl
```

Каждый запуск CLI `review` заново проверяет указанный коннектор; сохранённый PASS
не принимается вместо выполнения. Проверка подтверждает только испытанную
команду/конфигурацию, **не отсутствие других сетевых путей**. Интегратор обязан
проверить покрытие реально используемых протоколов и запрет прямого обхода;
при неподтверждённом покрытии работа с приватным контекстом остаётся BLOCKED.

Поставляемый `builtin_connector.py` проверяет границу данного Python-контроллера.
CLI `run` использует его автоматически. Это НЕ коннектор OpenCode/Codex/IDE:
подставлять его для доказательства их защиты нельзя. Нативные коннекторы пока
не поставляются; внешний харнесс без своего коннектора не считается подключённым.

## Review и commit

В отдельном standalone clone один раз выполните:

```powershell
python -I -S -B 'C:/Program Files/CookSecurity/runtime-v1/scripts/trusted_runtime.py' install-hook --repo D:/isolated/task
```

CLI `run` и `review` требуют установленный штатный hook и один
`--adapter-config`. Для `review` также обязателен `--harness-config`; он
не запускает генерацию, но использует её модель/config для отдельного review. Существующие hooks/core.hooksPath не заменяются:
они дают BLOCKED до отдельной проверенной интеграции. Текущий автоматический
проверяющий поддерживает только свой штатный hook, а не произвольные цепочки.

Python API `run()` принимает один `backend` для обоих этапов. `review_only=True`
пропускает генерацию, сохраняя отдельный review через тот же backend. Каждый
`complete()` получает только текущий публичный payload; адаптер не хранит историю
и не добавляет её к запросу. Встраивающий Python-код — доверенный координатор:
он сам вызывает `require_hook()` и `check_connector()` до работы. CLI выполняет
эти шаги сам. Нет API для отдельного reviewer или `--security-config`.

Последовательность: защищённая генерация → тесты → отдельный защищённый
review той же моделью → проверка JSON → разрешение конкретного HEAD/tree либо возврат на
исправление. Critical/High и ошибки блокируют commit; Medium/Low дают warning.
После любого изменения кандидата нужен новый review. Feedback перед передачей
генератору также проходит локальный gateway.

Credentials выбранной модели нужны для живой проверки; отдельный ключ DeepSeek
не нужен. Credentials не подключают перехватчик и не создают разрешения на раскрытие кода.
