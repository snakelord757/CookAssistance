# Явный допуск обезличенного контекста

`loop-disclosure-v2` запрещает отправку по умолчанию. Allowlist файлов ограничивает чтение/запись проекта, но **не даёт права передавать их содержимое**. Проверка regex — только дополнительный слой после допуска. Модель не может разрешить отправку сама.

## Доверенная граница

Оператор хранит `releases.json` вне генерируемого checkout, с правом записи только у себя/доверенного процесса согласования. Встроенному execution loop файл задаётся через `--release-policy`. Отдельный Gateway не нужен; при использовании необязательного HTTP-интерфейса ему задаётся та же policy. Гейт перечитывает её перед каждым запросом; нет файла, испорчен JSON, запись отозвана или данные изменились — BLOCK без upstream. CLI запрещает policy и локальный quarantine внутри целевого checkout. Запускайте генератор/тесты без прав записи в каталог policy; Python CLI не заменяет ACL/VM изоляцию.

Разрешение содержит:

- Случайный `id` и явный `approved: true` после локального просмотра.
- `input_sha256` точного исходного объекта `{stage, system, context}`; этот хэш не уходит провайдеру.
- Точные локальные замены `private → public`. Правила могут включать ФИО, адреса, нестандартные токены, комментарии, имена файлов и ключи JSON. Это буквальные одновременные замены, не regex; переносы строк запрещены, чтобы сохранить file/line.
- Полный обезличенный `export` и `export_sha256`, проверенные оператором. Пустой список замен означает, что оператор просмотрел весь текст и явно классифицировал его как не содержащий чувствительных данных, а не «сканер ничего не нашёл».

Допуск связан с **полным** запросом. Любое изменение task, кода, system prompt, feedback, дополнительных полей или этапа требует нового просмотра. Нет wildcard, доверия к целому каталогу, разрешения на произвольный будущий текст или автоматического переноса допуска с генерации на security review.

## Подготовка

По умолчанию отклонённые данные не пишутся на диск и не отправляются даже локальному Gateway. Для офлайн-разбора оператор может явно включить `--capture-context D:/private/quarantine` при запуске CLI. При отсутствии допуска CLI остановится и сохранит приватный исходный объект в новый UUID-файл. **Это карантин с исходными чувствительными данными**, не лог и не файл для LLM. Ограничьте доступ средствами ОС, не коммитьте/не загружайте его и удалите после согласования. На Windows `chmod` не задаёт полноценную ACL: каталог должен быть защищён оператором заранее.

Создайте локальный JSON правил, например:

```json
[
  {"private": "Синтетический Заказчик", "public": "REDACTED_PERSON_1"},
  {"private": "customers/private-person/module.py", "public": "file_1.py"}
]
```

Подготовьте черновик офлайн:

```powershell
python scripts/context_release.py --request D:/private/quarantine/REQUEST_ID.json --redactions D:/private/redactions.json --out D:/private/draft.json
```

Команда не делает сетевых вызовов, не перезаписывает существующий файл и **всегда выставляет `approved: false`**. Наличие черновика не разрешает отправку. Он включает локальные исходные значения замен — обращайтесь с ним как с секретным файлом.

Оператор должен прочитать **весь** `export`: system prompt, task, код, ключи/пути, feedback и метаданные. Удалите неоднозначные данные через правила и заново подготовьте черновик; если невозможно оценить чувствительность или сохранить необходимый для review контекст — не выдавайте допуск. Проверка хэша сама по себе не является проверкой обезличивания.

Только после такой проверки переключите `approved` в `true` и добавьте запись в операторский файл:

```json
{"schema_version": 1, "releases": []}
```

В `releases` помещаются полные подготовленные записи. Не редактируйте только export/hash вручную: исходная привязка и результат преобразований должны совпадать. Клиент и Gateway не принимают согласование из JSON запроса, текста модели или файлов целевого проекта.

## Возобновление

Для первого запроса повторите исходную команду. Если генерация уже завершилась и остановка произошла перед security review, добавьте `--resume-stage security`; CLI повторит тесты текущего кандидата и запросит отдельный допуск для review. Если High/Critical требует исправления, следующая генерация с feedback также получает отдельный допуск. После его просмотра возобновляйте с `--resume-stage generation`. Старый feedback проверяется по HEAD и содержимому файлов. При изменении кандидата старый допуск не подходит.

Локальный Gateway выдаёт только `export`. Execution loop передаёт его отдельному адаптеру модели; Gateway не зависит от модели и не делает исходящих вызовов. Исходные пути восстанавливаются локально в ответах по alias. Исходные значения внутри кода **не восстанавливаются**: изменять файл, содержимое которого было обезличено, запрещено. Это предотвращает перенос замаскированного секрета в логи/сетевой вызов через сгенерированный код. Для такой правки сначала локально уберите чувствительные данные из файла либо используйте изолированную локальную модель.

## Доказательства и пределы

Audit пишет `BLOCK` для непропущенного контекста и `RELEASED` с request/release ID для явно допущенного экспорта. `ALLOW_CLEAN` отдельно означает только прохождение DLP. Ни приватный контекст, ни исходные значения замен в audit не попадают. Gateway возвращает сверенный export из политики, не отражает произвольные данные клиента. Только после этого отдельный адаптер может вызвать модель. У Gateway нет provider endpoint/ключа, параметра model, JSON mode или парсера choices.

Тесты отправляют реальные HTTP-запросы к локальному Gateway и проверяют содержимое вызовов синтетического upstream: ФИО/адреса без regex-срабатываний не отправляются без допуска; одобренные значения заменены; прямой обход/подмена/отзыв/новый feedback блокируются до upstream. Тесты обычной механики loop отдельно устанавливают допуски для известных синтетических фикстур; production-код этого не делает.

Механизм гарантирует соответствие отправки конкретному операторскому разрешению. Он не может доказать, что человек правильно классифицировал произвольный текст. Ошибочно одобренный export без корректных замен остаётся ошибкой доверенного оператора. При сомнении политика требует отказ, а не автоматическое разрешение по отсутствию совпадений regex.
